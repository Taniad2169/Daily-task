Full step-by-step instructions & troubleshooting (click to open)

A. Run a real scan (about 2 minutes)

  1. Type the prospect's website in Prospect Website, pick the industry, then click Run Deep Audit. The sniffer code is now copied to your clipboard.
  2. Open a new Incognito window (Ctrl+Shift+N). Incognito means no old cookies, so you see what a first-time visitor sees.
  3. Make sure ad blockers / privacy extensions are off in Incognito. They block trackers and would hide what is really there.
  4. Go to the page you want to test (the home page, or better, the appointment / contact / intake page).
  5. Do not click the cookie banner (not Accept, not Decline). We are testing what happens before consent.
  6. Wait about 10 seconds so the trackers have time to fire.
  7. Press F12 (Chromebook: Ctrl+Shift+J) and click the Console tab.
  8. Click inside the Console, paste (Ctrl+V), press Enter. If Chrome asks, type allow pasting, press Enter, then paste again.
  9. Wait 10 to 20 seconds while it checks the links. You'll see "[WebSwan] Scan captured" and "Copied to your clipboard."
  10. Come back here, go to Tab 2, paste into the box and click Analyze. The dashboard, scores and report all update.

B. What the scan checks (5 pillars)

  • Tracking before consent: which pixels actually sent data before the visitor chose.
  • Cookie banner: is there one? If yes: Reject button, Settings, does it really block trackers, cookies set early, Privacy Policy and "Do Not Sell or Share" link (California). If none, it says No cookie banner.
  • ADA / WCAG 2.1 AA: Accessibility Statement or widget, alt text on images (with file names), labels, button and link names, color contrast, headings, page language, zoom, skip link.
  • HIPAA risk: sensitive form fields on pages where pixels send data, patient/booking pages with pixels, forms over http or GET, outside form tools that need a BAA. It flags risk; it is not a legal ruling.
  • HTTPS & broken links: HTTPS, insecure files and forms, and up to 50 site links + 25 outside links tested.

C. The WebSwan score

  • No cookie banner and no accessibility statement/widget = 10/100.
  • Only one of the two = 40/100.
  • Both = 50 to 100, depending on how well they pass the checks.

D. What the tracker colors mean

  • Sent data: the tracker made a real network request to Meta, Google, etc. before consent. This is your strongest finding.
  • Loaded: the tracker code downloaded but no data request was seen yet.
  • In source only: the tracker is written in the page code but did not load. Mention it as housekeeping, never as "sending data."
  • Pillars that weren't measured show "—" instead of a made-up number.

E. Print or save the client report

  1. Click Preview & Print Client Audit Report.
  2. Print / Save as PDF opens Chrome's print window. For a PDF choose Destination → Save as PDF, turn on Background graphics under More settings, then Save.
  3. Download PDF saves the file straight to your Downloads folder (no print window).
  4. Your photo is top-left and your WebSwan logo top-right on the report header.

F. Good habits

  • Scan the intake / booking page: that is where pixels next to health or legal questions matter most.
  • Save the JSON with the date (paste it into a note in WorkPilot) so you have proof of what you saw that day.
  • After you fix a client's site, scan again and send the new green report as before/after proof.
  • The report is a technical scan, not legal advice. Keep the outreach friendly and curious.

G. If something doesn't work

  • Print button does nothing: you're inside a preview window (Gemini, Claude, an email app). Open this file directly in Chrome or from its web link.
  • "Copied to your clipboard" didn't show: select the JSON text the Console printed, copy it by hand, and paste it in Tab 2.
  • "Could not read" error in Tab 2: make sure you pasted the whole thing, from the first { to the last }.
  • No trackers found but you expected some: check that ad blockers are off, wait 10 more seconds, and run the sniffer again.
  • Red errors in the Console that aren't from WebSwan: those belong to the prospect's own website. Ignore them.

Active Network Collection vs. Static HTML Tag Verification

Unlike basic scanners that only check if a <script> tag is visible in page source, WebSwan's v2 engine distinguishes between Dormant Static Tags (no network payload sent) and Active Runtime Beacons (POST /tr/, navigator.sendBeacon, and first-party _fbp / _ga cookies) that actively transmit visitor metadata prior to consent.

—

Data requests to a tracker's servers were seen during the test page load, before any cookie choice.

TRACKING COOKIES SEEN
—

Persistent client IDs (_fbp, _ga, _gcl_au) readable on the site after the page loaded.

LOADED OR IN CODE ONLY
—

The tracker is on the site, but no data request was seen during the test page load.

    }
  };
  const queue = [...IN.map(u => [u, true]), ...EX.map(u => [u, false])];
  await Promise.all(Array.from({ length: 6 }, async () => { while (queue.length) { const [u, i] = queue.shift(); await checkOne(u, i); } }));
  await new Promise(r => setTimeout(r, 200));
  document.removeEventListener('securitypolicyviolation', onCsp);
  // links blocked by the prospect site's own security policy are not counted as broken
  for (let i = broken.length - 1; i >= 0; i--) { const b = broken[i]; if (!b.internal && [...cspBlocked].some(x => x.includes(b.url.split('/')[0]))) { notChecked.push(b.url); broken.splice(i, 1); } }
  const links = { total: allLinks.length, uniqueInternal: internal.length, uniqueExternal: external.length, checkedInternal: IN.length, checkedExternal: EX.length, broken, slow: slow.slice(0, 10), notChecked: [...notChecked, ...httpSkipped].slice(0, 10) };

  const report = {
    version: 'webswan-sniffer-4', domain: location.hostname, url: location.href, timestamp: new Date().toISOString(),

        Penalty facts used in the emails & sources (checked October 2026)
        
    
          
  • HIPAA: $145 to $73,011 per violation, yearly cap $2,190,294 (HHS 2026 adjustment). Applies to healthcare providers and their vendors.
    • 
          
  • BAA: a signed contract can't be seen from a website, so the scan flags vendors that would need one (outside form/booking tools on patient pages) and pixels whose companies don't sign BAAs (Meta, Google, TikTok). Ask the practice for their BAA list.
    • 
          
  • ADA Title III: 8,667 federal lawsuits in 2025 (CA 3,252 • FL 1,823 • NY 1,471). Usually the business pays to fix the site plus attorney fees.
    • 
          
  • California CIPA: $5,000 per violation in private lawsuits over website tracking without consent. Bill SB 690 may limit some claims; still pending.
    • 
          
  • California Unruh Act: at least $4,000 per violation for accessibility barriers (courts may treat a whole website as one violation).
    • 
          
  • CCPA/CPRA: $2,663 per violation or $7,988 if intentional, only for businesses over $26.6M revenue or 100,000+ Californians' data.
    • 
          
  • Washington MHMDA: people can sue for damages, attorney fees and up to triple damages (max $25,000).
    • 
          
  • New York SHIELD Act: up to $5,000 per violation for failing to keep reasonable data safeguards.
    • 
          
  • Texas: HB 300 $5,000 to $1.5M per year for health information; TDPSA up to $7,500 per violation (30-day cure; most small businesses exempt except for selling sensitive data).
    • 
          
  • Florida: the Digital Bill of Rights only covers $1B+ companies, so emails for Florida use HIPAA and ADA facts instead.
